## Filling in the placeholders

For each placeholder service the first migration ticket should:

1. Boot the upstream service locally, or point at a dev/staging instance.
2. Fetch its `/swagger/v1/swagger.json` (or `/openapi.json`) over the placeholder,
   then regenerate the typed client — `nswag run <config>` where a config exists at
   the repo root, otherwise by hand.
3. Commit both `contracts/<service>.openapi.json` AND
   `Services/Generated/<Service>Client.cs` in the same commit so the contract
   diff and code diff are reviewed together.

## Why not start every service locally now?

The brief for T-migrate-gateway-shell explicitly says: "Do NOT start services
to fetch live specs — that's brittle and risky here." We respect that. The
placeholders make the BFF shell compile and run; live specs land per-service
in their migration tickets.

## jeeb-state-service (Layer-2 durable rewire — ADR-001-rev2)

`jeeb-state-service.openapi.json` is the LIVE spec fetched from
`http://127.0.0.1:10073/swagger/v1/swagger.json` and the
`JeebStateServiceClient.cs` is generated from it via `nswag run nswag-state.json`.
Probed live 2026-06-04; every endpoint exercised. Freshness is **not** gated
automatically — check the spec against the client by hand before merging.

### Contract gaps found (reported, NOT worked around)

These block a *complete* R2–R7 rewire and the full bounce-survival proof. The
gateway implements durable write-through for each (writes land; the
security-critical revocation/transition/strike rows now survive a bounce), but
cannot RECONSTRUCT its in-memory query index from the state-service after a
bounce because the service is keyed by its own opaque ids:

1. **No read-by-domain-key endpoints.** `GET /v1/state/kyc/{id}`,
   `refresh-families/{familyId}`, disputes by `caseId` are keyed by the
   state-service's own GUID. The gateway queries by `userId` / `tokenHash` /
   `deliveryId` / `contextId`. Needed:
   - `GET /v1/state/refresh-families/by-hash/{tokenHash} → {subject, familyId, status}`
     (R2: reconstruct identity on refresh-after-bounce without embedding userId
     in the opaque token).
   - `GET /v1/state/kyc?subject={userId}&latest=true` (R3: latest draft after bounce).
   - `GET /v1/state/disputes?deliveryId=… | contextId=…` (R5: active-case lookup).
2. **Create/open ops do not echo the new id via the typed client.**
   `POST refresh-families`, `POST disputes`, `POST kyc` are documented `200/201`
   with no response schema, so NSwag generates `Task` (void). The gateway can't
   capture `familyId`/`caseId`/`submissionId`. Document a 201 response body.
3. **PUT /idempotency and several POSTs documented as `200` with no body.**
   Forces a read-after-write (`GET /idempotency/{key}`) to learn `inserted` and
   recover the original body. Works, but doubles the hop. Document the response
   bodies (`inserted`, `outcome`, `count`, `acquired`) in the OpenAPI so the
   typed client returns them.
4. **`POST /v1/state/cancellations/bump` returns 500 for every well-formed
   request** (probed repeatedly with date-only `windowStart`). R6 cancellation
   counter is durable-write-blocked until the server-side bug is fixed. Strikes
   (the other half of R6) work fine.

### What IS fully bounce-survivable today (1:1 contract)

- **R1 idempotency** — `PUT /idempotency` + `GET /idempotency/{key}`; the key IS
  the domain key. Replay returns the original after a gateway bounce.
- **R8 locks + rate-limit** — keyed by `lockKey` / `bucket`; 409 = held.

## unified-payment-gateway (UPG) — contract REMOVED 2026-07-26, code REMOVED 2026-07-27

**Owner directive, 2026-07-26:** Jeeb no longer treats `unified_payment_gateway`
as a mandated payments destination. The prior "payments only via UPG" constraint
is **withdrawn for Jeeb** (it remains in force for other olivium product lines,
and the UPG service itself is untouched).

The following were deleted from this repo because they had **zero call sites**:

- `contracts/unified-payment-gateway.openapi.json` — the committed UPG spec.
- `Services/Generated/ServiceUnifiedPaymentGatewayClient.cs` — its NSwag client.
  Its only consumer was `Services/Clients/UpgRefundAdapter.cs`, which was itself
  never registered in DI (and asked `IHttpClientFactory` for a named client,
  `"UnifiedPaymentGateway"`, that was never registered anywhere).
- `Services/Clients/UpgRefundAdapter.cs` — dead adapter, never wired.
- `nswag-upg.json` and its generation-config row — the config whose only output
  was the deleted client.

### What survived the 2026-07-26 pass — and was removed on 2026-07-27

**Superseding owner ruling, 2026-07-27:** *"do not use UPG, jeeb is only cash on
delivery."* The 2026-07-26 pass deleted only the zero-call-site artefacts above
and deliberately left the live UPG code paths in place as evidence of a real
runtime dependency. That residue is gone as well. Nothing in this repo dials
unified-payment-gateway, and no configuration key can make it.

- `Services/Clients/HttpPaymentRefundClient.cs` — the dispute-resolve refund
  (money OUT) — is deleted. `IPaymentRefundClient` is deliberately KEPT so the
  call sites in `Disputes/V2/DisputeCaseService.cs` stay visible; the single
  registered implementation is `Services/Clients/CashOnDeliveryNoRefundClient.cs`,
  and it **throws**. Under cash-on-delivery there is no capture to reverse, and
  the prior in-memory fallback reported success without moving money.
- `Financials/Cod/IUnifiedPaymentCodClient`, its HTTP implementation and
  `UnifiedPaymentCodOptions` are deleted — the whole `Financials/Cod/` directory
  is gone. `Controllers/CodSettlementComposeController.cs` keeps all three routes
  (`POST api/v1/payments/cod/record`,
  `GET api/v1/payments/cod_jeeb/by-delivery/{id}`,
  `POST admin/v1/settlements/{batchId}/mark-paid`) with unchanged status codes and
  body shapes, but serves them from `ISettlementService`: gwdbx W2-R11 made
  settlement-service the ledger of record, so the settlement row IS the COD record.
- `Financials/IUpgSettlementClient.cs`, `UpgSettlementClient.cs` and
  `UpgSettlementLedgerClient.cs` are deleted, together with the
  `FeatureFlags:UseUpstream:Payments` flag that gated them. **There is no env var
  that arms UPG.** The flag was removed rather than left at `false`, because a flag
  that still looks live but is wired to nothing is an instrument that lies; setting
  `FeatureFlags__UseUpstream__Payments=true` today does exactly nothing. Its
  tombstone is the `_comment_payments_REMOVED` key in `appsettings.json` and
  `appsettings.Production.json`, and `scripts/gwdbx-flag-registry.txt` carries the
  name as a permanently `forbidden` row (G-05).
- `Services:UnifiedPayment:BaseUrl` is gone from committed config; its tombstone is
  `_comment_UnifiedPayment_REMOVED` in `appsettings.Production.json`. It held the
  last banned-host destination in this repo's own settings, and
  `scripts/no-50-allowlist.txt` EXCEPTION 2 is **RESOLVED / CLOSED 2026-07-27** —
  nothing here is pending an owner decision. (EXCEPTION 1, ten `.50`
  `workflow_dispatch` defaults in a deploy workflow, is a separate and still-open
  item.)
- The UPG readiness probe is gone from `Extensions/HealthCheckExtensions.cs`, which
  now carries a do-not-re-add comment in its place; the critical money probe is
  `settlement-service`. `tests/JeebGateway.IntegrationTests/Bff/UpgHealthProbePathTests.cs`
  is deleted — it asserted the probe MUST exist and had inverted from a safety net
  into pressure to re-add UPG. The standing guard is
  `tests/JeebGateway.IntegrationTests/Payments/NoPaymentGatewayDialGuardTests.cs`, a
  UTF-16-aware scan of the built assembly (an ASCII-only grep produced a false
  absence here once).

Do not re-add a payments destination, a `Services:UnifiedPayment:*` key, or a
`FeatureFlags:UseUpstream:Payments` flag without a new owner ruling.
